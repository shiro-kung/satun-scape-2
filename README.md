# Satun Scape — คู่มือติดตั้งใช้งานจริง

เว็บไซต์แนะนำการท่องเที่ยวจังหวัดสตูล (ไม่ใช่เว็บราชการ) ทำเป็นโปรเจกต์วิชาคอมพิวเตอร์
ใช้ PHP ธรรมดา + ไฟล์ JSON แทนฐานข้อมูล เหมาะกับโฮสติ้งแบบ shared hosting ทั่วไปที่รองรับ PHP
(ไม่ต้องมี MySQL หรือ Node.js บนเซิร์ฟเวอร์)

## ก่อนอัปโหลดขึ้นโฮสต์จริง — ทำ 3 ข้อนี้ก่อนเสมอ

### 1. ตั้งรหัสผ่านแอดมินของตัวเอง

ไฟล์ `config/admin.config.php` ที่แนบมาด้วยตั้งรหัสผ่านสุ่มให้แล้ว (ดูรหัสได้ในตัวไฟล์ —
มันเป็นคอมเมนต์อยู่ด้านบน) ใช้ล็อกอินที่ `/admin/` เพื่อดูรายการจองและข้อความติดต่อ

**แนะนำให้เปลี่ยนเป็นรหัสของตัวเองก่อนใช้งานจริง:**

```bash
php -r "echo password_hash('รหัสผ่านใหม่ของคุณ', PASSWORD_DEFAULT), PHP_EOL;"
```

แล้วเอาผลลัพธ์ไปแทนค่า `password_hash` ใน `config/admin.config.php`

### 2. ใส่อีเมลจริงที่จะรับการจอง/ข้อความติดต่อ

เปิด `config/email.config.php` แล้วแก้ `company_email` เป็นอีเมลจริงของทีม
(ตอนนี้เป็นอีเมลตัวอย่าง `booking@satunscape-tours.com` — ถ้าไม่เปลี่ยน อีเมลแจ้งเตือนจะส่งไม่ถึงใครจริง
แต่ระบบจะยังบันทึกทุกการจอง/ข้อความไว้ใน `/admin/` เสมอ ไม่มีอะไรหายแม้อีเมลจะยังไม่ทำงาน)

โฮสต์ส่วนใหญ่ (เช่น cPanel) เปิดใช้ฟังก์ชัน `mail()` ของ PHP ให้อัตโนมัติ แต่บางที่ต้องตั้งค่า SMTP เพิ่ม
— ถ้าอีเมลไม่ออกให้ลองถามฝ่ายซัพพอร์ตของโฮสต์

### 3. แก้โดเมนใน 3 จุดนี้ (ตอนนี้ยังเป็น `satunscape.example.com` ซึ่งเป็นโดเมนตัวอย่างที่ตั้งใจให้ไม่ resolve จริง)

- `robots.txt` — บรรทัด `Sitemap:`
- `sitemap.xml` — ทุกบรรทัด `<loc>`
- แท็ก `og:url` ในแต่ละหน้า `.html` (ใช้ Find & Replace ในโปรแกรมแก้โค้ดจะเร็วสุด)

## อัปโหลดขึ้นโฮสต์

1. อัปโหลดทุกไฟล์/โฟลเดอร์ขึ้นไปที่ root ของเว็บ (เช่น `public_html/`)
2. ให้แน่ใจว่าโฟลเดอร์ `data/` เขียนได้ (permission 755 หรือ 775 แล้วแต่โฮสต์) — ระบบจะสร้างไฟล์
   `data/users.php`, `data/bookings.php`, `data/messages.php`, `data/ratelimits.php` ให้เองตอนใช้งานครั้งแรก
3. ถ้าโฮสต์มี SSL (HTTPS) แล้ว เปิดไฟล์ `.htaccess` แล้วลบเครื่องหมาย `#` หน้าบล็อก "Force HTTPS"
   ด้านล่างสุดของไฟล์ (อย่าเปิดก่อนมี SSL เพราะเว็บจะเข้าไม่ได้เลย)
4. ทดสอบ: สมัครสมาชิก 1 บัญชี, ลองจองทัวร์ 1 รายการ, ส่งฟอร์มติดต่อ 1 ครั้ง แล้วเข้า `/admin/`
   ดูว่าขึ้นครบทั้งสามอย่างไหม

## มีอะไรอยู่ในนี้แล้วบ้าง (ไม่ต้องทำเพิ่ม)

- ระบบสมัคร/ล็อกอิน/ลืมรหัสผ่าน พร้อม CSRF protection, honeypot กันบอท, และ rate limiting
  กันการยิงลองรหัสผ่าน/สแปมฟอร์มรัว ๆ
- แผงแอดมิน (`/admin/`) ดูและอัปเดตสถานะการจอง + ข้อความติดต่อ, escape ข้อมูลผู้ใช้ครบ (กัน XSS)
- หน้า 404 ของเว็บเอง (ไม่ใช้หน้า error เริ่มต้นของโฮสต์)
- 9 ภาษา (ไทย/อังกฤษ/จีน/ตากาล็อก/มลายู/อาหรับ/สเปน/เกาหลี/ญี่ปุ่น) ครบทุกข้อความ

## ข้อจำกัดที่รู้อยู่แล้ว (เหมาะกับโปรเจกต์วิชาคอม ไม่ใช่เว็บระดับองค์กร)

- เก็บข้อมูลเป็นไฟล์ JSON ไม่ใช่ฐานข้อมูลจริง — รองรับผู้ใช้หลักสิบถึงหลักร้อยคนสบาย ๆ
  แต่ไม่เหมาะกับทราฟฟิกจำนวนมาก
- ไม่มีระบบชำระเงินในตัว — การจองส่งไปให้ผู้ประกอบการทัวร์ติดต่อกลับเพื่อตกลงราคา/ชำระเงินเอง
  (ตามที่ออกแบบไว้ตั้งแต่แรก ไม่ใช่ช่องโหว่)
- Rate limiting เป็นแบบเบื้องต้น (นับจาก IP) กันสแปม/บรูตฟอร์ซทั่วไปได้ แต่ไม่ใช่ระบบป้องกันระดับองค์กร
